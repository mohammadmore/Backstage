# ای‌ونت مستر (Backstage)

سیستم مدیریت رویداد: تعریف خدمات/پکیج/میکروتسک، ویزارد پرزنت، اتاق فرمان رویداد، فاکتور، تخصیص نیرو و داشبورد کارمندان.

- **بک‌اند:** PHP 8.1+ و MySQL/MariaDB (بدون فریم‌ورک، مناسب هاست اشتراکی cPanel)
- **فرانت‌اند:** React 18 + Tailwind، ساخته‌شده با Vite (دیگر کامپایل در مرورگر انجام نمی‌شود)

## ساختار پروژه

```
backend/            فایل‌های سمت سرور (عیناً روی هاست کپی می‌شوند)
  api.php           تنها نقطه ورود API
  .htaccess         محافظت از فایل‌های حساس
  inc/              تنظیمات، توابع مشترک و مهاجرت دیتابیس (از وب غیرقابل دسترس)
    config.sample.php
  uploads/.htaccess جلوگیری از اجرای هر اسکریپتی در پوشه آپلود
frontend/           کد React (src/)
tools/seed.php      ورود ۱۰۰ سرویس نمونه (فقط از خط فرمان)
scripts/            اسکریپت‌های ساخت بسته نهایی
```

## ساخت نسخه نهایی

```bash
npm install
```

```bash
npm run zip
```

خروجی: پوشه `dist/` و فایل `event-deploy.zip` که مستقیم روی هاست آپلود می‌شود.

## نصب / به‌روزرسانی روی هاست

> **قبل از هر کاری از دیتابیس (phpMyAdmin → Export) و پوشه فعلی `event` نسخه پشتیبان بگیرید.**

1. **رمز دیتابیس را عوض کنید** (cPanel → MySQL Databases)، چون رمز قبلی داخل کد بوده است.
2. در پوشه `event` روی هاست این فایل‌ها/پوشه‌های قدیمی را **حذف کنید**:
   `seed.php`، `error_log`، `api.php`، `index.html`، پوشه `assets`.
   **پوشه `uploads` را حذف نکنید** (عکس‌های پروفایل و لوگوها داخل آن است).
3. محتوای `event-deploy.zip` را داخل پوشه `event` آپلود و Extract کنید.
4. فایل `inc/config.sample.php` را با نام `inc/config.php` کپی کنید و اطلاعات دیتابیس (با رمز جدید) را در آن وارد کنید.
   - `storage_dir`: پوشه نشست‌ها و لاگ‌ها **بیرون از public_html** (مثلاً `/home/USERNAME/event-data`). اگر خالی بماند، خودکار پوشه‌ای کنار `public_html` ساخته می‌شود و فقط در صورت عدم امکان، داخل `inc/` (محافظت‌شده با `.htaccess`) ذخیره می‌شود.
   - `force_https`: ورود فقط روی HTTPS. اگر هاست گواهی SSL ندارد (توصیه نمی‌شود) آن را `false` کنید و بخش «انتقال اجباری به HTTPS» را در `.htaccess` حذف کنید.
5. سایت را باز کنید. در اولین درخواست، دیتابیس به‌صورت خودکار مهاجرت داده می‌شود:
   - رمزهای عبور فعلی هش می‌شوند (کاربران با همان رمز قبلی وارد می‌شوند)
   - زنجیره پیش‌نیاز تسک‌های رویدادهای موجود به ساختار جدید منتقل می‌شود
   - ایندکس‌های لازم ساخته می‌شوند
6. **اولین ورود هر کاربری که رمزش ضعیف است** (کمتر از ۸ کاراکتر، رایج مثل `123456`، یا شامل نام کاربری) به صفحه اجباری تغییر رمز می‌رود. این شامل حساب مدیر هم می‌شود.

> **HTTPS و HSTS:** سایت به‌صورت خودکار به `https://` منتقل می‌شود و هدر HSTS (۶ ماه) ارسال می‌شود. HSTS روی کل دامنه (مثلاً سایت فروشگاه روی همان دامنه) اثر دارد؛ یعنی مرورگرها آن دامنه را فقط با HTTPS باز می‌کنند. اگر بخشی از دامنه هنوز HTTPS ندارد، ابتدا آن را درست کنید.

> در به‌روزرسانی‌های بعدی، فقط محتوای zip جدید را جایگزین کنید؛ `inc/config.php` و `uploads` داخل بسته نیستند و دست نمی‌خورند.

### کاربر مدیر
کاربران با نقش `superadmin` (یا `admin`) پنل مدیریت را می‌بینند و بقیه داشبورد کارمند را. همکارانی که از پنل ساخته می‌شوند نقش `staff` دارند.

### داده نمونه (اختیاری)
روی سیستمی که به دیتابیس دسترسی دارد (پس از اینکه سایت یک بار باز شده و جداول ساخته شده‌اند):

```bash
php tools/seed.php /path/to/event/inc/config.php
```

اجرای دوباره، سرویس تکراری اضافه نمی‌کند.

## توسعه محلی

```bash
php -S 127.0.0.1:8080 -t backend
```

```bash
npm run dev
```

درخواست‌های `api.php` از سرور Vite به PHP محلی پراکسی می‌شوند.

## تغییرات نسخه ۲ (رفع ایرادات)

### امنیت
- **احراز هویت سمت سرور** با نشست (Session) و کوکی `HttpOnly`/`SameSite=Strict`. قبلاً هر کسی بدون ورود می‌توانست همه عملیات API (حذف، تغییر فاکتور، تغییر رمز کاربران) را انجام دهد.
- **کنترل دسترسی سمت سرور:** کارمند فقط وظایف خودش را می‌بیند/تغییر می‌دهد؛ اطلاعات پایه، فاکتور و لاگ‌ها فقط برای مدیر. تلفن و شبای همکاران دیگر برای عموم قابل دریافت نیست. نام کاربر در لاگ‌ها از نشست خوانده می‌شود، نه از درخواست.
- **رفع SQL Injection** در `update_sort` (نام جدول) و `get_notifications` (پارامتر role). همه کوئری‌ها Prepared Statement شدند.
- **هش رمزها** با `password_hash`؛ رمز پیش‌فرض `123456` حذف شد؛ نام کاربری یکتا.
- **سیاست رمز عبور:** حداقل ۸ کاراکتر، رد رمزهای رایج، دنباله‌های ساده و رمزهای شامل نام کاربری. کاربرانی که رمز ضعیف قدیمی دارند در اولین ورود مجبور به تغییر رمز می‌شوند و تا آن زمان به هیچ بخش دیگری دسترسی ندارند (سمت سرور اعمال می‌شود). رمزی که مدیر برای همکار تعیین می‌کند موقت است و در اولین ورود باید عوض شود. همه کاربران از دکمه 🔑 در هدر می‌توانند رمز خود را تغییر دهند.
- **باطل شدن نشست‌ها با تغییر رمز:** تغییر رمز (توسط خود کاربر یا مدیر) و خاموش کردن کاربر، همه نشست‌های باز او را روی دستگاه‌های دیگر فوراً می‌بندد.
- **HTTPS اجباری:** انتقال خودکار به HTTPS، هدر HSTS، کوکی `Secure`، و رد ورود/تغییر رمز روی HTTP.
- **نشست‌ها و لاگ‌ها بیرون از وب‌روت** ذخیره می‌شوند (حتی روی سرورهایی که `.htaccess` را نمی‌خوانند قابل دانلود نیستند).
- **محدودیت تلاش ورود** (۱۰ تلاش ناموفق در ۱۵ دقیقه برای هر IP).
- **محافظت CSRF** (هدر اختصاصی برای همه درخواست‌های POST) و حذف `Access-Control-Allow-Origin: *`.
- **آپلود امن عکس:** بررسی نوع و ابعاد واقعی، بازسازی تصویر با GD، محدودیت حجم، حذف فایل قدیمی هنگام تعویض/حذف؛ اجرای اسکریپت در `uploads` مسدود شد.
- رمز دیتابیس از کد خارج شد (`inc/config.php` خارج از گیت و غیرقابل دسترس از وب).
- `seed.php` از روی هاست حذف و به ابزار خط فرمان تبدیل شد.
- پیام خطای دیتابیس دیگر به کاربر نمایش داده نمی‌شود و `error_log` از وب قابل دریافت نیست.
- جلوگیری از تزریق فرمول در خروجی‌های اکسل (CSV).

### باگ‌های عملکردی
- **تایید واگذاری از زنگوله مدیر کار نمی‌کرد** (`from_user_id` ارسال نمی‌شد و تراکنش با خطا برمی‌گشت؛ لاگ هم روی رویداد اشتباه ثبت می‌شد). اکنون سرور اطلاعات را از خود درخواست می‌خواند. تایید/رد از تب «تخصیص‌ها»ی اتاق فرمان هم اضافه شد (دکمه‌ای که قبلاً بی‌عمل بود).
- **زنجیره پیش‌نیاز** با عنوان تسک و داخل نقش ذخیره می‌شد و در تسک‌های هم‌نام، تسک اشتباه را قفل/آزاد می‌کرد (در داشبورد کارمند حتی بین رویدادهای مختلف). اکنون با `depends_on_id` و محدود به همان پکیج ذخیره و قفل در سرور هم اعمال می‌شود. مدیر می‌تواند تسک قفل را از قبل به کسی تخصیص دهد.
- ثبت سرویس «بدون دسته» در MySQL حالت strict خطا می‌داد.
- با حذف یک دسته، سرویس‌هایش از ویزارد ناپدید می‌شدند (اکنون به «سایر خدمات» می‌روند). حذف مکان/سازمانِ در حال استفاده و حذف همکارِ دارای وظیفه باز مسدود شد.
- ورودی‌های فاکتور پس از تغییر تعداد مهمانان مقدار قدیمی را نشان می‌دادند.
- ویرایش تعداد در ردیف دستی فاکتور، مبلغ آن را پاک می‌کرد.
- تقویم شمسی همه ماه‌ها را ۳۱ روزه نشان می‌داد (تاریخ اشتباه ذخیره می‌شد)، تاریخ پیش‌فرض ۱۴۰۳ نمایش داده می‌شد ولی ذخیره نمی‌شد، و سال‌ها ثابت بودند. بررسی «پایان بعد از شروع» اضافه شد.
- تاریخ‌ها در سافاری (آیفون) نامعتبر خوانده می‌شدند (تایمر و فاز رویداد).
- وضعیت «در حال اجرا» در کارت‌ها «پیش‌نویس» نمایش داده می‌شد.
- داشبورد کارمند جزئیات همه رویدادها را یکی‌یکی دریافت می‌کرد (کند و نشت اطلاعات).
- تشخیص پکیج انتخاب‌شده با بخشی از نام انجام می‌شد؛ پیش‌فاکتور اکنون با تعداد مهمانان نهایی محاسبه و قیمت‌ها در سرور از روی پکیج خوانده می‌شود.
- تخصیص گروهی نقش برای هر تسک یک درخواست جدا و یک بارگذاری کامل می‌فرستاد.
- درخواست واگذاری تکراری و واگذاری وظیفه دیگران ممکن بود.
- لاگ‌ها مشخص نمی‌کردند کدام وظیفه/ردیف تغییر کرده است.
- با رفرش صفحه کاربر از سیستم خارج می‌شد؛ «خروج» نشست را در سرور نمی‌بست.
- «جایگزینی سریع» وظایف انجام‌شده را هم منتقل می‌کرد (سابقه انجام‌دهنده از بین می‌رفت).
- دکمه حذف عکس در آپلودر زیر ورودی فایل پنهان بود و کار نمی‌کرد.
- فرم‌های افزودن پس از ثبت خالی نمی‌شدند (ثبت تکراری) و در صورت خطا داده‌ها پاک می‌شدند.
- ویرایش پکیج/تسک در پکیج‌ساز آن را از لیست برمی‌داشت و ترتیب (و پیش‌نیازها) به هم می‌ریخت.
- ورودی‌های عددی با صفحه‌کلید فارسی کار نمی‌کردند.
- تایمر رویداد روی موبایل نوار ناوبری را می‌پوشاند؛ هدر اصلی روی پنجره ویزارد قرار می‌گرفت.
- «لینک پورتال کارفرما» یک آدرس جعلی و غیرفعال می‌ساخت؛ تا پیاده‌سازی واقعی این قابلیت حذف شد.

### تجربه کاربری (نسخه ۲.۲)
- پنجره‌های پیش‌فرض مرورگر (`alert`/`confirm`/`prompt`) با پنجره‌ها و پیام‌های داخل برنامه جایگزین شدند (پیام موفقیت/خطا، تایید حذف، فرم‌های ورودی).
- بازخورد ذخیره: نوار پیشرفت بالای صفحه هنگام ذخیره، پیام موفقیت، و نشانگر «✓ ذخیره شد» کنار فیلدهای فاکتور.
- آدرس (URL) برای هر صفحه: `#/events`، `#/events/12/finance`، `#/master/services`؛ دکمه بازگشت مرورگر و رفرش درست کار می‌کنند و لینک رویداد قابل اشتراک است. صفحه پیش‌فرض مدیر «رویدادها» است.
- بستن ویزارد ساخت رویداد (✕، Esc، کلیک بیرون، دکمه بازگشت مرورگر یا بستن تب) در صورت وجود اطلاعات، تایید می‌خواهد.
- ویرایش (عنوان/نقش/فاز) و حذف وظیفه؛ ویرایش شرح و حذف ردیف فاکتور.
- جستجو و فیلتر وضعیت و مرتب‌سازی در لیست رویدادها (رویدادهای پایان‌یافته به‌صورت پیش‌فرض پنهان)؛ جستجو در همه لیست‌های دیتابیس و فیلتر دسته در خدمات.
- ویزارد: مراحل نام‌دار و قابل پرش، نمایش تعداد انتخاب‌ها در هر مرحله، نمایش سرویس‌های پنهان‌شده با دلیل، نمایش مکان‌ها بدون نیاز به تعداد مهمان، و پیش‌فاکتور با جزئیات ردیف‌ها.
- داشبورد کارمند: مرتب‌سازی بر اساس تاریخ، جداسازی رویدادهای گذشته، گروه‌بندی وظایف بر اساس فاز با نشان «فاز فعلی»، گزینه «فقط کارهای باقیمانده» و خلاصه کارهای باقیمانده.
- اعلان‌ها: تعداد روی زنگوله، رفتن به رویداد مربوطه با کلیک، دکمه جداگانه «خوانده شد» و «همه خوانده شد».
- انقضای نشست: پنجره ورود مجدد روی همان صفحه باز می‌شود و اطلاعات صفحه از بین نمی‌رود.
- اعداد: نمایش ارقام فارسی و جداکننده هزارگان در فیلدهای مبلغ، با پذیرش تایپ فارسی و انگلیسی.
- طراحی سبک‌تر: وزن فونت و اندازه تیترها متعادل شد، سایه‌های اضافی حذف شد.
- دسترس‌پذیری: حلقه فوکوس واضح برای صفحه‌کلید، برچسب برای همه دکمه‌های آیکونی و فیلدها، کنتراست بهتر متن‌ها، کارت تسک قفل خوانا، پشتیبانی Esc در پنجره‌ها.
- حالت تیره: صفحه ورود هم تم ذخیره‌شده (یا تم سیستم‌عامل) را رعایت می‌کند و کارمندان هم دکمه تغییر تم دارند.
- دیتابیس: مرتب‌سازی با کشیدن و رها کردن (روی دسکتاپ) کنار دکمه‌های جابجایی؛ فرم روی موبایل جمع‌شونده است و ویرایش روی دسکتاپ صفحه را جابجا نمی‌کند.
- برش عکس با اسلایدر اندازه و چرخ ماوس؛ انتخاب عکس با دکمه یا کشیدن فایل (کلیک روی کادر دیگر پنجره انتخاب فایل را باز نمی‌کند).
- فاکتور روی موبایل به‌صورت کارت نمایش داده می‌شود و نسخه قابل چاپ / PDF دارد.

### کارایی
